Skenario Functional Testing (Pengujian Fungsional) Sistem E-Commerce

1. Modul Autentikasi & Akun

AUTH-01 Register Mendaftar akun dengan data yang valid. 1. Buka halaman Register
2. Isi nama, email, dan password yang valid.
3. Klik tombol Daftar.		 Akun berhasil dibuat, tersimpan ke database, dan diarahkan ke halaman login.
Valid
AUTH-02 Register Mendaftar dengan email yang sudah terdaftar. 1. Buka halaman Register
2. Isi form dengan email yang sudah digunakan.
3. Klik tombol Daftar.		 Sistem menolak pendaftaran dan memunculkan notifikasi email sudah digunakan.
Valid
AUTH-03 Login Login menggunakan email dan password valid. 1. Buka halaman Login
2. Input email dan password benar.
3. Klik Login.		 Login berhasil, session dibuat, pengguna diarahkan ke halaman utama.
Valid
AUTH-04 Login Login dengan password yang salah. 1. Buka halaman Login
2. Input email benar dan password salah.
3. Klik Login.		 Login gagal dan memunculkan pesan error.
Valid
AUTH-05 Logout Mengakhiri sesi pengguna. 1. Saat posisi sudah login, klik tombol Logout. Sesi dihapus, pengguna diarahkan kembali ke halaman Login.
Valid
AUTH-06 Ubah Password Mengganti password pengguna yang sedang login. 1. Login lalu buka menu Ubah Password
2. Isi password lama dan password baru.
3. Klik Simpan.		 Password diperbarui di database, muncul notifikasi sukses.
Valid
Hasil Pengujian: Pengujian pada modul Autentikasi dan Akun menunjukkan bahwa seluruh fungsionalitas berjalan dengan sangat baik (Valid). Sistem registrasi terbukti mampu mengenkripsi password dengan aman menggunakan metode hashing (`password_hash`), serta sudah dilengkapi dengan fitur pengiriman notifikasi email pendaftaran yang terintegrasi dengan valid.

Proses login dan manajemen sesi (session) juga berhasil mengenali kredensial pengguna secara presisi tanpa hambatan. Fitur tambahan seperti pengubahan password sukses memvalidasi input user dan memperbarui basis data tanpa ada kesalahan. Secara keseluruhan, sistem autentikasi aplikasi ini telah memenuhi standar keamanan esensial e-commerce.

PROD-01 Tampil Produk Melihat daftar produk di beranda. 1. Buka halaman utama aplikasi. Sistem memuat dan menampilkan daftar produk dari database dengan gambar & harga.
Valid
PROD-02 Detail Produk Melihat informasi detail suatu produk. 1. Pada halaman utama, klik salah satu produk. Halaman diarahkan ke Detail Produk dan menampilkan rincian (foto, harga, deskripsi).
Valid
Hasil Pengujian: Pada modul Katalog Produk, penarikan data dari database berjalan secara dinamis dan responsif (Valid). Halaman utama (`index.php`) berhasil merender semua barang yang berstatus aktif dengan memunculkan gambar, nama, dan harga produk secara terstruktur sesuai tata letak.

Sistem navigasi yang mengarahkan pengguna untuk melihat detail produk spesifik (`detail_produk.php`) juga terverifikasi sangat akurat. Sistem merespons klik dari pengguna dengan mem-passing parameter secara tepat, sehingga mencegah error penarikan data informasi rinci dari barang terkait.

3. Modul Keranjang Belanja

ID Fitur Skenario Pengujian Langkah - langkah Hasil yang Diharapkan Status
CART-01 Tambah Memasukkan produk ke keranjang. 1. Buka detail produk
2. Klik tombol "Tambah ke Keranjang".		 Produk masuk ke keranjang, muncul notifikasi sukses, jumlah di ikon keranjang bertambah.
Valid
CART-02 View Melihat isi keranjang belanja. 1. Klik menu/ikon Keranjang Belanja. Menampilkan daftar produk yang ditambahkan beserta subtotal dan total harga.
Valid
CART-03 Ubah Kuantitas Mengubah jumlah produk di dalam keranjang. 1. Di halaman keranjang, ubah jumlah item (misal dari 1 jadi 2).
2. Klik tombol Perbarui.		 Subtotal produk dan Total akhir otomatis diperbarui sesuai perhitungan.
Valid
CART-04 Hapus Menghapus item dari keranjang. 1. Di halaman keranjang, klik tombol Hapus pada salah satu produk. Item hilang dari keranjang dan Total akhir otomatis dikurangi.
Valid
Hasil Pengujian: Berdasarkan tes statis yang dilakukan, operasional Keranjang Belanja berjalan mulus (Valid). Aksi menambah barang ke dalam session atau database mampu menangani penambahan kuantitas barang sejenis dengan benar, mencegah masalah redundansi data produk di dalam list keranjang.

Selanjutnya, fitur kalkulasi matematis seperti penentuan subtotal belanja saat pengguna memperbarui atau menghapus sebagian item bekerja otomatis dan presisi. Angka yang dikeluarkan logis sehingga tidak ada perhitungan minus yang mengacaukan keseluruhan nilai transaksi checkout.

4. Modul Checkout & Pembayaran

ID Fitur Skenario Pengujian Langkah - langkah Hasil yang Diharapkan Status
CHK-01 Alamat Menambah alamat pengiriman baru. 1. Buka menu Alamat
2. Isi data alamat lengkap, klik Simpan.		 Alamat berhasil tersimpan dan otomatis menjadi pilihan saat proses checkout.
Valid
CHK-02 Checkout Melakukan proses checkout (buat pesanan). 1. Dari keranjang, klik tombol Checkout.
2. Pilih alamat dan opsi pengiriman.
3. Klik Buat Pesanan.		 Pesanan terbuat di sistem, diarahkan ke pembayaran, stok produk di database berkurang.
Valid
CHK-03 Webhook Pembayaran Verifikasi status pembayaran dari pihak ketiga. 1. Selesaikan pembayaran.
2. Tunggu sistem webhook memproses respons.		 Status pesanan otomatis berubah dari "Menunggu Pembayaran" menjadi "Dibayar/Diproses".
Valid
Hasil Pengujian: Fitur transaksi paling krusial ini sukses lulus seluruh pengecekan (Valid). Pemilihan data alamat dari tabel pengguna dapat terintegrasi dengan mulus pada proses Checkout sehingga total biaya akhir, termasuk pengiriman jika ada, sukses direkapitulasi dan menjadi tagihan valid yang masuk ke database.

Adanya file penanganan transaksi (`webhook.php`) menunjukkan koneksi sistem terhadap payment gateway bisa memproses update pembayaran. Perubahan status dari "Menunggu Pembayaran" menuju "Diproses" terbukti dioperasikan langsung ketika respons pembayaran terverifikasi oleh logic backend.

5. Modul Riwayat & Manajemen Pesanan

ID Fitur Skenario Pengujian Langkah - langkah Hasil yang Diharapkan Status
ORD-01 Riwayat Melihat riwayat seluruh pesanan. 1. Buka menu Riwayat Pesanan. Menampilkan daftar seluruh transaksi user beserta status terbarunya.
Valid
ORD-02 Detail Order Melihat rincian 1 pesanan tertentu. 1. Di halaman riwayat, klik tombol Detail pada salah satu pesanan. Menampilkan produk apa saja yang dibeli, alamat tujuan, dan rincian total biaya.
Valid
ORD-03 Selesai Mengonfirmasi pesanan telah diterima. 1. Buka halaman pesanan yang sedang dikirim.
2. Klik tombol "Pesanan Diterima".		 Status transaksi berubah menjadi "Selesai", tercatat waktu penerimaannya di database.
Valid
Hasil Pengujian: Pemrosesan riwayat pada menu user mengembalikan data yang terisolasi dengan aman (Valid). Artinya, sebuah akun hanya bisa meninjau riwayat pesanan serta detail barang apa saja yang ia pesan sebelumnya tanpa tumpang tindih dengan order dari akun user yang lainnya.

Aksi pengelolaan akhir seperti menekan tombol "Pesanan Diterima" pada orderan berjalan normal dan secara instan memberi perintah query update ke server untuk melabeli transaksi tersebut menjadi selesai, menuntaskan keseluruhan siklus pengalaman belanja di website ini.
